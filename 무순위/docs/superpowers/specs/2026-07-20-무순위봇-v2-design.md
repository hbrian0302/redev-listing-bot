작성일: 2026-07-20
대상: `무순위/` 파이프라인
상태: 설계 확정, 구현 전

---

## 1. 문제 정의

무순위 봇이 라이브로 돌고 있으나 스레드/인스타에서 반응이 없다.

최초 가설은 "**금액 혜택이 너무 적어서**"였고, 그에 따른 대응안으로 "스레드를 더럽히지 말고 인스타 스토리/하이라이트로 강등, 강추만 피드 게시"가 검토됐다.

검증 결과 **가설은 방향은 맞았으나 원인 지점이 틀렸다.** 문제는 채널이 아니라 **발행 필터가 비율(%) 기준이라 저가 단지의 푼돈 마진을 상위 등급으로 승격시키고 있던 것**이다. 채널 전환은 기각하고 필터·결정어·캡션을 재설계한다.

## 2. 실측 데이터 (근거)

`data.go.kr` 무순위 공고 API(`getRemndrLttotPblancDetail`) 수도권 326건 직접 조회, 2026-07-20 기준.

| 항목 | 실측값 |
|---|---|
| 공고일 → 접수시작 리드타임 | 중위 **5일** (188/326이 정확히 5일, 최소 3일, 75%=7일) |
| 접수기간 길이 | **265/326건이 단 하루** (중위 1일, 최대 6일) |
| 주당 신규 공고 | 중위 **4건** (범위 2~11건, 최근 26주) |
| 공급세대수 | 1세대 64건 / 2세대 37건 / 3세대 27건 / 4세대 11건 |
| 발행 이력 | `queue/published` **2건**, 둘 다 접수 마감 전 발행 (타이밍 정상) |

### 발견 1 — 결정어가 비율 기준이라 판단이 왜곡됨 (핵심)

`margin.py`의 `decide()`가 `cheap_pct` 기준으로만 등급을 매긴다.

```
cheap >= 15%  → "무조건 신청!"
cheap >=  5%  → "고민해볼만해요"
cheap >  -5%  → "애매한 가격대"
그 외         → "촉수엄금!"
```

이 때문에:

- 5억 단지가 15% 싸면 **마진 7,500만 원**인데 "무조건 신청!"으로 승격
- 30억 단지가 5% 싸면 **마진 1.5억**인데 "고민해볼만해요"로 강등

실제 발행된 평택 고덕 건은 `gap 0.38억`으로 "고민해볼만해요" 판정을 받고 나갔다. 사용자 기준으로는 애초에 발행되면 안 되는 물건이었다. **반응 부재의 구조적 원인.**

### 발견 2 — 캡션에 접수일이 없음

현행 캡션에 접수 시작·마감일이 전혀 없다. 접수기간이 대부분 **하루**인데 "살까말까"만 말하고 "언제까지"가 빠져 있어, 독자가 읽어도 행동할 수 없다.

### 발견 3 — 승인 큐 정렬이 마감일을 무시함

`publish.py:37-38`의 `oldest_approved()`가 승인 큐를 **파일 mtime 오래된 순**으로 뽑는다. 마감 임박 건이 뒤로 밀린다. 현재는 발행량이 적어 사고가 안 났지만, 컷을 올리면 후보가 희소해져 큐 체류시간이 늘고 검수 대기 중 마감이 지날 확률이 커진다.

### 기각된 가설 — "세대수가 적어서(당첨 확률)"

326건 중 139건이 4세대 이하라는 분포를 근거로 "복권이라 정보 가치가 없다"는 가설을 세웠으나 **기각**. 무순위는 확률이 0에 수렴해도 **기대수익이 크면 사람이 몰린다**. (실사례: 기대수익 5억대 물건에 1세대 모집, 약 30만 명 신청) 세대수는 게이팅 기준으로 쓰지 않는다. 사람을 움직이는 변수는 **절대 기대수익**이다.

## 4. 설계

### 4.1 결정어 재설계 (`margin.py`)

`gap = bunyang - sise` (음수 = 시세보다 쌈). 마진 = `-gap`.

**절대액 사다리**

| 마진 | 결정어 | 행선지 |
|---|---|---|
| +1.5억 이상 | 무조건 신청! | **피드 게시** |
| +0.5 ~ +1.5억 | 고민해볼만해요 | blog_pool |
| -0.5 ~ +0.5억 | 애매한 가격대 | blog_pool |
| -0.5억 이하 (비쌈) | 촉수엄금! | blog_pool |

**비율 가드** — 절대액이 컷을 넘어도 `cheap_pct < 3%`이면 한 단계 강등한다. 고가 단지에서 1.5억 차이가 시세 추정 오차 범위일 수 있기 때문이다. 절대액 등급과 비율 등급이 충돌하면 **항상 낮은 쪽**을 채택한다.

**신뢰도 가드** — 기존 `confidence(n)` 유지. `very_low`(표본 3건 미만)는 절대액과 무관하게 피드 게시 금지, blog_pool로 보낸다.

### 4.2 데이터 필드 추가 (`datagokr.py`)

`musunwi_list()`가 현재 버리고 있는 필드를 보존한다.

- `SUBSCRPT_RCEPT_BGNDE` / `SUBSCRPT_RCEPT_ENDDE` — 접수 시작/마감 (D5, D6)
- `RCRIT_PBLANC_DE` — 공고일
- `PBLANC_URL` — 청약홈 원문 링크 (블로그용)
- `TOT_SUPLY_HSHLDCO` — 공급세대수 (게이팅엔 안 쓰되 블로그 본문 재료)

### 4.3 큐 안전장치 (`publish.py`)

- `oldest_approved()` → `urgent_approved()`: **접수마감일 오름차순** 정렬
- 발행 직전 마감일 재확인, `마감일 < 오늘`이면 발행하지 않고 `queue/expired/`로 이동
- 마감일 정보가 없는 건은 기존 mtime 순서로 폴백

### 4.4 캡션 생성

숫자·사실 반복은 카드가 담당하고, 캡션은 **"왜 이 가격인가 / 누가 넣나 / 언제까지"** 만 말한다.

**구조**

| 행 | 스레드 | 인스타 |
|---|---|---|
| 훅 | 스치니들 호칭 + 판정 1행 | 동일 |
| 근거 | 비교 시세 1개만 | 비교 시세 + 배경 해석 |
| 대상 | (생략) | 누가 넣어야 하나 |
| 마감 | 접수일 + D-N | 접수일 + D-N |
| CTA | 좋아요/팔로우 | 좋아요/팔로우 + 이유 |
| 면책 | (생략, 문장에 출처 녹임) | 1행 |
| 길이 | 6~7행 / 약 200자 | 12~15행 |

**금지 사항**
- `분양가 X vs 시세 Y` 식 라벨:값 덤프 (카드와 중복)
- 내부 약어 노출 — `(브역대신평공초)`, `입지 60점 B등급`
- 단정·명령형 — `무조건`, `~해라`, `이건 함정이다`
- 캡션 내 텔레그램 링크

**무날조 가드** — "계약 취소분이라 앞사람이 잔금을 못 쳤다" 같은 해석 문장은 파이프라인 숫자에 없다. LLM으로 생성하되 **숫자·지명·날짜는 파이프라인이 넘긴 fact 딕셔너리 값만 사용**하도록 강제한다. 재미나이 글생성기에 이미 적용된 방식과 동일하게 간다. fact에 없는 수치가 캡션에 등장하면 해당 건을 pending으로 되돌린다.

### 4.5 확정 캡션 샘플

**스레드 — 강추 (예시 수치)**
```
스치니들~ 이번 줍줍은 좀 봐야 할 듯.

같은 단지 84타입이 지난달 9억에 팔렸는데
이번 무순위가 7억이더라고. 2억 차이.
계약 취소분이라 물건 하자는 아니래.

접수 7월 25일 딱 하루야. D-3

도움 됐으면 좋아요~ 줍줍 계속 올릴 테니 팔로우도 부탁해🙏
```

**인스타 — 강추 (예시 수치)**
```
스치니들~ 이번 건 좀 봐야 할 것 같아.

같은 단지 84타입이 지난달 9억에 팔렸는데
이번 무순위가 7억이더라고. 2억 차이야.
계약 취소분이라 물건이 이상한 게 아니라
그냥 앞사람이 잔금을 못 친 거래.

전세 끼고 들어갈 수 있는 무주택자면 한번 볼 만하고,
현금 3억 정도는 있어야 당첨돼도 지킬 수 있으니까
계산은 미리 해보고 넣는 게 좋아.

접수는 7월 25일 딱 하루야. D-3.

도움 됐으면 좋아요~ 수도권 줍줍 계속 올릴 테니
팔로우해두면 놓칠 일 없어🙏
```

경고형 캡션 톤도 검토·확정했으나 D3에 따라 **피드에는 사용하지 않는다.** 블로그 프로젝트에서 재사용할 수 있도록 본 문서에 톤 레퍼런스만 남긴다.

### 4.6 채널·유입 구조

```
캡션 → 좋아요/팔로우        (피드에서 완결)
프로필 링크 → 텔레그램 @your_handle   (심화 상담)
```

캡션에서 매번 외부로 빼내면 스레드·인스타 모두 도달이 깎이므로 2단 구조로 둔다.

## 5. 범위 밖 (별도 프로젝트)

**네이버 재개발 블로그** — 컷 미만 물건의 검색 트래픽 수확용. 계정 미개설 상태이고 목적·발행기준·최적화가 무순위 봇과 완전히 다르다.

| | 무순위 봇 | 네이버 블로그 |
|---|---|---|
| 목적 | 유입 + 전문가 자산 | 검색 트래픽 |
| 발행 기준 | 마진 1.5억↑ 희소 게시 | 전량 아카이브 |
| 최적화 | 임팩트·즉시성 | SEO·키워드·누적 |
| 계정 | 있음 (재미나이) | 없음 |

본 스펙에서는 **`queue/blog_pool/`에 JSON을 적재하는 접점까지만** 구현한다. 블로그는 별도 브레인스토밍 → 스펙 → 구현 사이클로 진행한다.

## 6. 리스크·한계

| 리스크 | 내용 | 대응 |
|---|---|---|
| **발행량 고갈** | 컷 1.5억 + 강추만(D3) → 월 2~4건 추정. 계정이 조용해져 알고리즘 도달이 죽을 수 있음 | 구현 첫 단계에서 실제 통과율을 측정한다. 월 2건 미만이면 컷을 1.2억으로 내리거나 D3 재검토 |
| **컷 통과율 미검증** | 1.5억은 실제 마진 분포를 계산하지 않고 정한 값이다 (사용자 직관 "1억 언더는 왜 굳이" 기반) | 326건 전체 마진 배치 계산 후 컷별 월 발행량 표를 만들어 재확인 |
| **시세 추정 오차** | `margin.py` 폴백이 "시군구 신축 유사평형 중위(광역참고)"까지 내려간다. 이 경우 1.5억 차이가 실제 마진이 아닐 수 있음 | 비율 가드 3% + `confidence` very_low 게시 금지로 방어. 그래도 남는 위험 |
| **IG 액션블록** | `ig_publish.py` 주석대로 웹 자동게시는 블록 위험. 발행량이 줄면 위험도 함께 감소 | 스토리 미도입(D10)으로 빈도 추가 증가 없음 |
| **LLM 캡션 날조** | 해석 문장 생성 시 없는 사실을 지어낼 수 있음 | fact 화이트리스트 강제 + 검수봇 최종 승인 (사람 게이트 유지) |

## 7. 구현 순서 (writing-plans로 이관)

1. 마진 분포 배치 계산 → 컷별 예상 발행량 확인 (리스크 선검증)
2. `datagokr.py` 필드 보존
3. `margin.py` 결정어 절대액 재설계 + 가드
4. `pipeline.py` 라우팅 — 피드 발행 / `blog_pool` 분기
5. `publish.py` 마감일 정렬 + 만료 폐기
6. 캡션 생성기 이원화 (스레드/인스타) + 무날조 가드
7. dry-run 검증 후 launchd 재시작 ⚠️ *상주 워커는 재시작 안 하면 옛 코드로 계속 돈다*

## 부록 — 이 결론에 도달한 사고 과정 (CoT)

### 출발점

깔고 있던 전제는 두 가지였다. (1) 반응이 없는 이유는 금액 혜택이 적어서다. (2) 따라서 시시한 물건을 스레드에서 치우고 스토리/하이라이트로 강등하면 피드가 깨끗해진다.

즉 **문제를 "콘텐츠 배치"의 문제로 규정**하고 출발했다.

### 검증·반박

전제 (2)부터 무너졌다. 스토리 강등은 콘텐츠 가치를 올리는 게 아니라 안 보이게 숨기는 조치라, "그럼 왜 계속 만드나"에 답이 없었다. 게다가 `ig_publish.py`에 이미 "IG 웹 자동게시는 액션블록 위험 → 소량·간헐"이라 적혀 있어, 스토리를 매일 밀면 정작 중요한 강추 게시가 블록으로 막힐 수 있었다.

전제 (1)은 **부분적으로만 맞았다.** 실제 원인은 더 아래에 있었다. `margin.py`의 결정어가 비율 기준이라 5억 단지의 7,500만 원 마진이 "무조건 신청!"으로 승격되고 있었다. 실제 발행된 평택 고덕 건(`gap 0.38억`)이 "고민해볼만해요"로 나간 것이 증거다. **"혜택이 적은 물건이 올라간다"가 아니라 "혜택이 적은 물건을 상위 등급으로 올려주는 로직이 있다"** 가 정확한 진단이었다.

### 판단 기준의 진화

중간에 **틀린 가설을 하나 세웠다가 사용자 반박으로 폐기**했다. 공급세대수 분포(326건 중 139건이 4세대 이하)를 보고 "1세대짜리 복권이라 정보 가치가 없다 = 당첨 확률이 문제"라고 판단했다.

사용자 반박: *"복권이기 때문에 오히려 열광하는 거지. 허나 기대수익이 커야 하는 거지. 확률 문제 아님."* (실사례: 기대수익 5억대 물건 1세대 모집에 약 30만 명 신청)

이 반박으로 게이팅 기준이 **세대수 → 절대 기대수익**으로 완전히 교체됐다. 초안에 있던 "10세대 이상 AND 마진 상위" 이중 게이트는 폐기하고 마진 단일 기준으로 단순화했다. 이것이 설계 전체를 바꾼 지점이다.

두 번째 진화는 **타이밍**이다. "주간 묶음" 초안에 사용자가 *"신청기한이 지나지 않을까"* 라고 물었고, API 실측(리드타임 중위 5일 / 접수기간 265건이 하루)으로 **주 1회 고정 요일은 실제로 놓친다**는 것이 확인됐다. 다만 이후 컷 미만 물건을 블로그로 보내기로 하면서 묶음 발행 자체가 사라져, 주기 논의는 무의미해지고 **큐 정렬·만료 안전장치**만 남았다.

세 번째는 **톤**이다. 파이터 페르소나로 잡은 초안이 *"둘 다 단언적이고 고압적"* 이라는 지적을 받아, 호칭(스치니들)과 어미(`~같아`, `~하더라고`)를 낮춘 공유형으로 교체했다. 이어 스레드 길이 지적으로 채널별 이원화가, CTA 지적으로 텔레그램 유도 → 좋아요/팔로우 전환이 확정됐다.

### 근거 (사실 / 추측 구분)

**측정된 사실** — 리드타임 중위 5일, 접수기간 265/326건이 하루, 주당 신규 4건, 세대수 분포, 발행 이력 2건 및 둘 다 마감 전 발행. 모두 `data.go.kr` API 직접 조회와 `queue/published` 파일 확인으로 얻었다.

**코드에서 확인된 사실** — `decide()`의 비율 기준 분기(`margin.py:57-64`), `oldest_approved()`의 mtime 정렬(`publish.py:37-38`), `datagokr.py`가 접수일·세대수 필드를 버리는 점, 캡션에 접수일 부재.

**사용자 경험 기반 (수치 미검증)** — "1억 언더면 왜 굳이", 기대수익 5억 물건에 30만 명 신청 사례. 컷 1.5억은 이 직관에서 나온 값이다.

**추측** — 발행량 월 2~4건 추정, 경고형이 저장·공유가 잘 된다는 관측, 외부 링크가 도달을 깎는다는 통설. 모두 미검증이며 리스크 표에 반영했다.

**중요한 한계** — "반응이 없다"는 최초 판단 자체가 **n=2** 표본에 기반한다. 발행 이력이 2건뿐이므로, 필터를 고쳐도 반응이 안 나올 가능성과 표본이 부족했을 뿐일 가능성을 현재로선 구분할 수 없다.

### 채택·기각 근거

- **채택 D1(절대액 결정어)** — 반응 부재의 구조적 원인을 직접 제거한다. 다른 모든 변경의 전제.
- **채택 D2(컷 1.5억)** — 1억은 수도권 신축 값 대비 체감이 약하고, 2억은 표본이 말라 계정이 죽는다. 중간값.
- **채택 D3(강추만)** — 경고형 1/3 제한(3안)을 추천했으나 사용자가 1안 선택. 피드 신뢰 신호를 우선하고 발행량 감소를 감수한다.
- **채택 D5(마감 안전장치)** — 사용자가 "매주 할 건데 필요한가" 물었으나, 주기가 아니라 **큐 체류시간**이 문제였다. 컷이 올라가면 후보가 희소해져 대기가 길어지고, 접수기간이 하루라 여유가 없다. 두 줄짜리 비용으로 "끝난 줍줍 게시" 사고를 막는다.
- **채택 D11(블로그 분리)** — 목적(트래픽 vs 유입)·발행기준(전량 vs 희소)·계정 상태가 모두 달라 한 스펙에 넣으면 둘 다 흐려진다.
- **기각 스토리/하이라이트(D10)** — 유입 기여 0(스토리는 팔로워 없으면 노출 거의 없고 하이라이트는 열람률 낮음), IG 액션블록 리스크 증가, 그리고 애초에 진단이 틀렸으므로 처방도 무효.
- **기각 세대수 게이트** — 위 "판단 기준의 진화" 참조. 확률이 아니라 기대수익이 변수다.
- **기각 주 2회 묶음 발행** — 컷 미만을 블로그로 보내기로 하면서 묶을 대상 자체가 사라졌다.
- **기각 캡션 내 텔레그램 CTA** — 1순위 목적이 팔로워 유입인데 매번 외부로 빼내면 도달이 깎인다. 프로필 링크로 2단 분리.

### 남은 불확실성

1. **컷 1.5억의 실제 통과율을 모른다.** 326건 전체 마진을 계산하지 않았다 (실거래 API 호출량 때문). 구현 1단계에서 반드시 선검증해야 하며, 결과에 따라 컷 또는 D3가 바뀔 수 있다.
2. **n=2 문제.** 반응 부재의 원인이 필터였는지 표본 부족이었는지 확정할 수 없다. 개선 후에도 반응이 없으면 진단을 다시 세워야 한다.
3. **시세 추정 신뢰도.** 폴백이 "시군구 광역참고"까지 내려가면 1.5억 마진이 실제 마진이 아닐 수 있다. 비율 가드와 confidence 게이트로 방어하지만 완전하지 않다.
4. **강추만 발행 시 도달 저하 정도를 예측할 수 없다.** 월 2~4건으로 계정이 유지될지, 알고리즘상 죽을지는 돌려봐야 안다.
5. **파이터 톤의 실효.** "스치니들" 호칭과 구어체가 2030 타겟에 먹히는지는 검증되지 않았다. 초기 몇 건의 반응으로 재조정 필요.
